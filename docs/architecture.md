# Architecture

Product context, constraints and stack: see `CLAUDE.md`. This file covers only how the code is organized. It's intentionally thin until the prototype (tasks T1–T6 in `docs/done.md`) has validated the TTS pipeline. Expect it to change.

## TTS pipeline

```
text ──► espeak-ng (phonemizer, built into sherpa-onnx) ──► IPA phonemes
     ──► tokens.txt (phoneme → integer ID)
     ──► model.onnx (Piper VITS net, run by onnxruntime inside sherpa-onnx)
     ──► Float32 PCM samples (22050 Hz for imre) ──► WAV file ──► audio player
```

App code makes one call: `OfflineTts.generate(text:, sid: 0, speed:)` → `GeneratedAudio{samples, sampleRate}`.
Voice files per voice (from sherpa-onnx's converted Piper releases):

```
vits-piper-hu_HU-imre-medium/
  hu_HU-imre-medium.onnx      # the net (~60 MB)
  tokens.txt
  espeak-ng-data/             # pronunciation rules, many small files
```

### Android gotcha: real file paths
Native code (sherpa-onnx/espeak-ng) needs real filesystem paths. Voices are downloaded and extracted into `getApplicationSupportDirectory()/voices/` (see `VoiceInstaller`); nothing is read from Flutter assets. Use `flutter-examples/tts` in https://github.com/k2-fsa/sherpa-onnx as the reference for exact API names. The Dart API has quirks (e.g. the parameter really is spelled `maxNumSenetences`).

### Threading
`generate()` is a synchronous FFI call and blocks the isolate it runs on. `PiperEngine` therefore spawns a long-lived background isolate that owns the `OfflineTts` (FFI pointers can't cross isolates): it loads the model, then receives text and returns WAV paths. Requests are handled in order, so one sent mid-load waits for the load. `dispose()` makes the isolate free the model and exit; switching voices = dispose the old engine, create a new one. `SystemEngine` is already async (platform channel).

## Code layout (target)

```
lib/
  main.dart               # app entry, MaterialApp
  voices/
    voice.dart            # Voice (id, language, gender, label, kind system|piper)
    voice_engine.dart     # abstract VoiceEngine + SynthResult; the only API callers use
    piper_engine.dart     # sherpa-onnx OfflineTts for one Piper voice (lengthScale 1.2)
    system_engine.dart    # flutter_tts synthesizeToFile → WAV, same playback path
    catalog.dart          # remote/bundled voice catalog, parsing + filtering
    voice_installer.dart  # download → sha256 → extract (isolate) → install/delete
  speech/speaker.dart     # Speaker: current VoiceEngine + player, speak(text), last-utterance reuse
  storage/database.dart   # drift tables (+ generated database.g.dart, committed)
  storage/lists_repository.dart  # the only storage API the UI uses; seeding, history, restore defaults
  lists/split_sentences.dart     # paste → sentences
  ui/                     # screens/widgets: speaking screen, editing screen, voice picker
  # later: recordings/, emergency/ (platform channel)
assets/seed/<lang>.json     # default sentence lists per UI language (seed data, read once on DB creation)
assets/catalog.json         # bundled fallback copy of voices/catalog.json (tool/sync_catalog.ps1)
voices/catalog.json         # curated downloadable voices (see CLAUDE.md "Voice delivery")
voices/samples/<id>.wav     # preview clips, generated by tool/make_samples.ps1 (same pipeline as the app)
tool/make_samples.ps1       # regenerates voices/samples (Python 3.12 venv via uv, sherpa-onnx pinned to the app's version)
tool/sync_catalog.ps1       # copies voices/catalog.json → assets/catalog.json (run after every catalog edit)
```

Rules:
- Android only (`flutter create --platforms android`). No iOS work yet.
- **Voice model files are never committed or bundled.** Installed at runtime into `<appSupport>/voices/<id>/`, with one shared `<appSupport>/voices/espeak-ng-data/`.
- Keep dependencies minimal. Approved: `sherpa_onnx`, `path_provider`, `audioplayers`, `flutter_localizations`, `intl`, `flutter_tts`, `shared_preferences`, `http`, `archive`, `crypto`, `package_info_plus`, `drift`, `drift_flutter` (dev: `drift_dev`, `build_runner`). Ask before adding others.
- UI strings in Hungarian. Code, comments and docs in English.
- Hungarian-first, not Hungarian-only. In the prototype, hardcoded strings are fine. After it, all UI strings move to Flutter's standard `gen-l10n` (ARB files, `hu` as the template locale). Never hardcode language-specific assumptions in logic. Language-specific things include preloaded phrases, the voice list and the emergency number, so treat them as per-locale data.

Licenses/About screen. State management: plain `setState` + drift `watch` streams; add a package only if that gets painful.

## Speaking (decided 2026-11-02)
- One **Mondd** button, no separate "Ismétlés". `Speaker.speak(text)` remembers the last `(voice id, normalized text)` → WAV path; the same key replays the WAV from the start without synthesizing, a new key synthesizes and deletes the previous WAV. Normalization: trim + collapse inner whitespace. This is "last utterance" only, not an audio cache (see `docs/TODO.md`).
- The free-text field keeps its text after speaking (so Mondd again = repeat) and has a ✕ to clear it. Older phrases are reachable through history.
- Sentence-row taps go through the same `Speaker.speak`, so tapping a row twice replays instantly.

## Storage (decided 2026-11-02)
SQLite via **drift** (typed tables/queries, migrations, reactive `watch` queries so e.g. a `said` change greys out a row without refresh code). Small settings (selected voice, last used list) stay in `shared_preferences`. The voice catalog stays JSON (read-only, hand-parsed; use `json_serializable` if more JSON types appear).

Tables (schema v1):
- `sentence_lists`: `id` PK, `title`, `kind` (`everyday | conversation | history`), `pinned` bool, `position` int, `seedKey` nullable unique, `createdAt`.
- `sentences`: `id` PK, `listId` FK (cascade delete), `text`, `position` int, `said` bool (default false), `recordingPath` nullable (message banking, later), `seedKey` nullable (unique per list), `spokenAt` nullable (history ordering), `createdAt`.
- `app_meta`: key/value (`seedLanguage`: the language the DB was seeded with, used by restore).
- Dart naming: the `sentences.text` column is the getter `body` (`text` clashes with drift's `Table.text()`), so `Sentence.body`.
- Exactly one `history` list; it can't be deleted or renamed, its title is localized via ARB at display time. History is newest first by `position`: a new row gets `min(position) - 1` (negative values are fine), so moving to the top never shifts other rows.
- Moving a sentence to another list drops its `seedKey` (it left its seed list); copies never have one.
- Generated code (`database.g.dart`) is committed. Regenerate after changing tables: `dart run build_runner build --delete-conflicting-outputs`.

Seed data: `assets/seed/<lang>.json`, inserted in drift's `onCreate` for the UI language (fallback `en`); afterwards they're ordinary rows the user can edit or delete. Changing the phone language later doesn't touch the DB.
```json
{ "lists": [ { "seedKey": "everyday", "title": "Alap", "kind": "everyday", "pinned": true,
               "sentences": [ { "seedKey": "water", "text": "Kérek vizet!" } ] } ] }
```

Restoring defaults is **non-destructive**: it only re-adds what's missing, never deletes or changes anything (so recordings, user-added and user-edited sentences are always safe).
- Per list ("Alapértelmezett mondatok visszaállítása"): re-insert the seed sentences whose `seedKey` isn't in the list anymore, at their seed position. An edited seed sentence keeps its `seedKey`, so it's not duplicated.
- Lists ("Alapértelmezett listák visszaállítása"): re-create seed lists whose `seedKey` is missing, with their seed sentences.
- The seed for restore is the one of the language the DB was created with (store it in a `meta` row or in `shared_preferences`).

History: every spoken text (row tap or free text) goes in; the same normalized text moves to the top instead of duplicating; capped at 30 (a constant, e.g. `historyCap`; nobody scrolls further than that instead of retyping), oldest dropped first, with no exceptions. History rows are their own `sentences` rows, so dropping one never touches a sentence in a permanent list. A recording only counts as kept if it is attached to a sentence in a non-history list. Once recordings exist, a recording file may only be deleted when no remaining `sentences` row references its `recordingPath` (copies can share the file).

## Voices
- `Voice` (id, language, gender, label, kind) + `VoiceEngine` interface (`load`, `synthesizeToWav`, `dispose`). Everything above this layer (UI, sentence lists, history) only sees `VoiceEngine` and WAV paths.
- `PiperEngine`: sherpa-onnx, loads an installed voice dir. `SystemEngine`: Android TTS via `flutter_tts`, also writes WAV files so playback is uniform.
- `catalog.dart`: remote catalog JSON (one URL constant) → bundled `assets/catalog.json` fallback. Only catalog voices can be downloaded. Skips unknown `schemaVersion` and entries with a newer `minAppVersion`.
- `voice_installer.dart`: download to temp → verify sha256 → extract in a background isolate → move into place. Nothing half-installed ever appears.

## Sentence lists (UI model, decided 2026-11-02)
There are no tiles. Everything speakable is a **sentence list**:
- `SentenceList { id, title, kind: everyday | conversation | history, pinned, layout: rows | grid, sentences[] }`, `Sentence { id, text, recordingPath?, said }`.
- The preloaded everyday phrases are one `everyday` list (per-locale data). Users add their own lists ("Orvos", "Éjszaka"); these replace Cboard-style folders.
- A **prepared conversation** is a `conversation` list: sentences track `said`, and a "Következő" button speaks the next unsaid one.
- **History** is an automatic `history` list (newest first, capped); any sentence in it can be spoken again or saved to another list.
- Message banking attaches a recording to any `Sentence`; playback uses the recording instead of TTS.
- v1 layout: rows only (prepared sentences are long and would be cut off in a grid). `grid` for short everyday phrases later, if users ask for it.

Main screen (speaking mode):
```
┌──────────────────────────────┐
│ [Alap] [Kati, holnap] [▾]    │  pinned list chips + expand button
├──────────────────────────────┤
│ Ki kéne cserélni a villany…  │  big rows, tap = speak
│ Légyszi vegyetek trappistát! │  (said = greyed out, still tappable)
│ Mi újság a suliban?          │
│           [ Következő ▶ ]    │  conversation lists only
├──────────────────────────────┤
│ [free text…………  ✕] [Mondd]   │  always visible
└──────────────────────────────┘
```

Interaction rules (the user may have weak, slow or shaky hands):
- **One tap = one fixed meaning.** Tapping a sentence always speaks it; tapping a chip always switches lists. Nothing on the speaking screen is editable.
- **No layout shifts under the finger.** Sections don't expand on tap. Layout only changes through a dedicated button.
- **Chips: pinned lists only** (e.g. Alap, the current conversation, Előzmények). Switching between them is one tap, which matters mid-conversation ("Kérek vizet!" from Alap, then back to the conversation). The **▾** button expands the chip row into a large grid of all lists over the sentence area; picking one collapses it and shows that list (as a temporary chip if it isn't pinned). Lists can be pinned/unpinned.
- The app opens on the last used list, so a conversation prepared in the evening is already open the next day.
- The free-text field is always visible. Focusing it brings up the keyboard (which takes the space); closing the keyboard gives the space back to the list. No extra code needed.

Editing mode (separate screen, used with no time pressure, e.g. the evening before a visit):
- One row per sentence (not one big text box: rows keep sentence ids, so recordings and `said` survive edits). Tap to edit, drag to reorder, delete, later record message-banking audio. An "add" field at the bottom: typed or pasted text is split into sentences (after `.`, `!`, `?`, `…` only when followed by whitespace + uppercase or a newline/end, plus every newline; keep the punctuation, Piper uses it). The uppercase rule keeps Hungarian ordinals and dates together ("a 3. emeleten", "2026. 11. 02.").
- From any list or history: "add to list" / move a sentence to another list.
- Conversation lists: "reset" (clear `said`) for reuse; carry unsaid sentences over to the next conversation.

Open questions (ask logopédusok / the ALS group, ideally with a paper or screenshot mockup): rows vs grid for everyday phrases; should a conversation list reset or disappear after the visit; do patients already prepare like this (paper, phone notes), and how.
